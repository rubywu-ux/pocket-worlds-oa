## Current focus: Part 4, Reception + Opening prototype

The receiving player opens the app and finds a gift waiting. Pocket Worlds provides this screen; the job is to bring the opening to life as a small prototype built with AI. Riffing on and extending the provided screen is encouraged.

The prototype must answer:
1. What is the opening animation?
2. How is the gift note shown together with the gift?
3. Is there any further connection between sender and recipient after opening?

Hard requirements:
- Delivered as a **live link**. Reviewers must be able to click through it and break it.
- **Built with code.** A screen recording, rendered video or GIF does not count, and pre-rendered motion (e.g. a Lottie/MP4 as the main moment) is on their avoid list.
- Must look like it ships in the same build as the provided screens. Don't invent a new visual language.
- AI use is required **and must be disclosed**. They want to see how Ruby directs the AI and where she overrules it.

## Prototype status (2026-10-04)

- Built and working: idle screen matching Figma, sprout → unboxing (lid pops off, the three-flower bloom sits behind the box framing it (box centered in front), gifts pop up and rest INSIDE the open heart box (bottoms behind the front wall) with a scale-in, glow + gentle bob, ×N badges on each gift), envelope → letter card slips out and waits for a tap → fades into the note reading view, open state (arrives with the gifts in the open box, then the lid drops back on: closed formal box; items list; note with rocking sticker underneath; Send a gift back / Visit Irene's garden toasts, close, replay), skip with a 450 ms double-tap guard, keyboard, reduced motion, phone / tablet / desktop layouts.
- Code map: `src/timeline.ts` (step timings), `src/App.tsx` (state machine), `components/Stage.tsx` (idle → bloom → letter/note overlay), `Gift.tsx`, `GiftItems.tsx` (gifts inside the box), `Letter.tsx` (from/sending-to card), `Note.tsx`, `OpenView.tsx`, `ClosedView.tsx`, `Particles.tsx`.
- **Variations (2026-10-04, per Ruby):** three exploration builds at https://rubywu-ux.github.io/pocket-worlds-oa/v1/, /v2/, /v3/. Each one has its own page (`prototype/vN/index.html`) and its own folder (`prototype/src/variants/vN/`: App, styles, components). They share `src/data.ts`, assets and fonts, plus `src/variants/shared/`: `feedback.ts` (Web Audio sound + haptics), `SoundToggle.tsx` (mute toggle and Skip pill) and `shared.css`. Vite builds all four pages (`vite.config.ts` → `rollupOptions.input`). Each shows a small "Vn · Name" tag. Ruby asked for completely different animation styles and flows in the Highrise / Picnic Gift Shop design language, plus Duolingo-style sound and haptics. Claude designed:
  - **V1 · Grow it:** press and hold to water (`GrowStage.tsx`, `GrowParts.tsx`). The note hangs as a gift tag and unrolls. The gift stays planted and in bloom.
  - **V2 · Pull the ribbon:** drag the tied envelope until the ribbon snaps; the gifts tumble onto a gingham blanket under the Picnic banner (`PicnicStage.tsx`, `PicnicParts.tsx`, `src/assets/picnic-sky.webp` = the banner's sky, cropped from a 1× Figma screenshot). Pull the letter out of the envelope; it flips to the note.
  - **V3 · Reward reveal:** an Offer Cell charges, then pops; three cards deal out and flip; Collect all sends the gifts to storage; one-tap sticker "thanks" reactions (`RewardStage.tsx`, `RewardParts.tsx`).

  Details are in SPEC.md §7 and the README Variations table. The main prototype (`src/`, link `/`) is unchanged and has no sound yet. To promote a variation, copy its files over `src/` (fixing `../../../data` imports back to `../data`) and bring `variants/shared/` along.
- QA gotchas for the variations: a drag or hold that *ends* the interaction must not count as a skip. The stage only skips on a *fresh* pointerdown during the automatic part (`skipArmed`). In V2, motion's `onTap` can fire after a short drag, so taps within 350 ms of a drag end are ignored (`lastDragEnd`). In Playwright, use `click({ force: true })` on swaying elements. Scripts live in the scratchpad (`pw/v1.mjs`, `v2.mjs`, `v3.mjs`).
- Deploy: `.github/workflows/deploy-prototype.yml` publishes `prototype/dist` to https://rubywu-ux.github.io/pocket-worlds-oa/ on every push. Pages is on (Source = GitHub Actions) and the site is live. Claude can't change Pages settings via the API.
- Art in `prototype/src/assets/` is Ruby's 4× Figma exports, converted to WebP (≈390 KB total), imported in `data.ts` so builds give each file a content hash (no stale browser cache), and preloaded in `main.tsx`. If art changes, regenerate `public/og.png` (link preview, 1200×630 of the bloomed state).
- Fonts are self-hosted via @fontsource (Google Fonts is blocked in the sandbox).
- Screenshot QA: Playwright with `executablePath: /opt/pw-browsers/chromium-1194/chrome-linux/chrome` against `npx vite preview --port 4173`.

## Working conventions

- **Commit and push often.** Do it after every meaningful step (a new concept sketch, a working interaction, a fix, a README/log update), not just at the end of a session, so nothing is lost if Ruby has to switch Claude accounts mid-task. Keep commits small with clear messages. Pull before starting work.
- Ruby directs and makes the design calls. Ask before structural decisions, and record in the README's AI-use log where she changed or overruled AI output.
- Local copy: on Ruby's Mac, in iCloud Drive › Ruby Workspace › Pocket Worlds (a clone of this repo).
- Git in that folder needs file-deletion permission, because git removes its own lock files. If a commit leaves `.git/*.lock` or `tmp_obj_*` files behind, remove them.
- GitHub: Claude can't create repos. Pushing needs GitHub connected on the current Claude account and the Claude GitHub App granted access to this repo.
- The repo is public, so never commit secrets or Pocket Worlds' template files.
